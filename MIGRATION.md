# Migration Guide

## Upgrading to v3

Version 3 has two breaking changes: it enforces canonical spelling of string IDs, and it removes
`Once.Prefixed`.

- If you use `db_format: :signed`, `:unsigned` or `:raw`, your stored IDs need no migration. You
  only need to make sure external input uses canonical spellings.
- If you store IDs as `:hex`, `:hex32` or `:url64`, follow [String ID spellings](#string-id-spellings).
- If you use `Once.Prefixed`, follow [Once.Prefixed](#onceprefixed). It is a mechanical change
  that you can make at any time before upgrading.

IDs generated by Once are always canonical.

### String ID spellings

A canonical ID is spelled the way Once generates it:

- `:hex` and `:hex32` are lowercase.
- `:hex32` and `:url64` have all unused trailing bits set to zero.

Version 3 rejects non-canonical spellings, including in external input and `Once.to_format/3`.

If you store IDs as `db_format: :hex`, `:hex32` or `:url64`, check and fix existing data
**before upgrading**:

1. Upgrade to >=2.2.0. This version adds `Once.Canonicalize` and the `:normalize` option, which
   the steps below use.
2. Check each format and relevant column:

   ```elixir
   Once.Canonicalize.check(MyApp.Repo, [{"users", "id"}], format: :hex)
   # => :no_migration_needed | {:need_migration, [{{"users", "id"}, 2}, ...]}
   ```

3. If the check reports non-canonical values, rewrite them with a migration, once per format,
   while still on v2. Listing the primary keys is enough, because foreign keys that reference
   them are detected and changed too:

   ```elixir
   defmodule MyApp.Repo.Migrations.CanonicalizeIds do
     use Ecto.Migration

     def up do
       Once.Canonicalize.up([{"users", "id"}, {"posts", "id"}], format: :hex)
       # a persisted prefix is the optional third element
       Once.Canonicalize.up([{"orgs", "id", "org_"}], format: :hex32)
     end

     def down, do: raise(Ecto.MigrationError, message: "irreversible")
   end
   ```

   It is recommended to test the migration on a production database copy first.

   The rewrite locks the tables against writers, so read the "Large tables" section of the
   [v2 `Once.Canonicalize` documentation](https://hexdocs.pm/once/2.2.0/Once.Canonicalize.html)
   first. The helper is removed in v3.

4. Once all relevant stored data is canonical, enable `normalize: true` in your Once
   configuration while still on v2, so that new values are canonical too.
5. Make sure nothing else reintroduces non-canonical values:
   - other writers of the same columns use canonical spellings
   - external references and cached IDs are canonical
6. Upgrade to v3 and remove the `:normalize` option in the same deployment. Version 3 rejects
   the option and enforces canonical spelling instead.

### Once.Prefixed

`Once.Prefixed`, deprecated since 1.1.0, has been removed. Use `Once` with the same `:prefix` and
`:persist_prefix` options instead.

In schemas, replace the type:

```elixir
# before
field :id, Once.Prefixed, prefix: "usr_", persist_prefix: true, autogenerate: true

# after
field :id, Once, prefix: "usr_", persist_prefix: true, autogenerate: true
```

## Upgrading to v2.0.0

In major version 2, nothing changed directly in Once itself.
However, it depends on `NoNoncense` 2.0 which introduces breaking changes in its bootstrapping procedure,
because it now offers proper machine ID lease management and monitoring.
Follow its [migration guide](https://hexdocs.pm/no_noncense/migration.html) to set up your NoNoncense instance and you are good to go.

## Upgrading to v1.0.0

Version 1.0.0 introduces breaking changes that follow from `NoNoncense` 1.0.0 breaking changes. Be sure to read its [migration guide](https://hexdocs.pm/no_noncense/migration.html).

**You only have to change anything if you are using encrypted IDs.**

In order to migrate to NoNoncense 1.x encrypted nonces without breaking its uniqueness guarantees, you **MUST NOT** change your key or cipher:

- pass your **existing** encryption key to `NoNoncense.init/1` new `:key64` option
- pass `:des3` to `NoNoncense.init/1` new `:cipher64` option

```elixir
# in application.ex (probably)
NoNoncense.init(
  name: Once,
  machine_id: NoNoncense.MachineId.id!(opts),
  cipher64: :des3,
  key64: System.get_env("ONCE_KEY")
)
```
